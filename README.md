# mtuci-timetable

Неофициальный Python-клиент к расписанию занятий МТУСИ.

Библиотека ходит в тот же AJAX-компонент Bitrix (`mtuci:timetable`), который
обслуживает страницу [mtuci.ru/time-table](https://mtuci.ru/time-table/).
Эндпоинт открыт: авторизация, токены и сессионный `sessid` не нужны.

Проект не связан с университетом. Публичного API у МТУСИ нет, эндпоинт
не задокументирован и может измениться без предупреждения.

## Установка

```bash
pip install mtuci-timetable
```

## Быстрый старт

```python
from datetime import date
from mtuci_timetable import TimetableClient

with TimetableClient() as client:
    group = client.resolve("БВТ2301")

    for lesson in client.timetable(group).on(date(2026, 9, 2)):
        print(lesson)
    # 09:30 Основы военной подготовки (Лекции) - И-2
    # 11:15 Основы военной подготовки (Лекции) - И-2
```

Поиск идёт по группам, преподавателям и аудиториям сразу:

```python
client.search("Таньков")
# [SearchItem(name='Таньков Олег Иванович', type=<EntityType.TEACHER>, value='Таньков Олег Иванович_3cba721c-...')]
```

Для преподавателя важно передавать в расписание именно `value`, а не ФИО:
сервер ждёт `ФИО_<guid>` и по одному имени ничего не отдаст. `resolve()`
делает это за вас, `timetable()` принимает результат напрямую.

## Отрезок дат

Сервер отдаёт расписание помесячно, окном от первого числа месяца примерно
до восьмого числа следующего. Метод `between()` склеивает нужные месяцы
и убирает пересечения:

```python
week = client.between("БВТ2301", date(2026, 9, 1), date(2026, 9, 7))
for day in week:
    print(day.date, len(day), "пар")
```

## Выбор группы по фильтрам

Тот же путь, что и на сайте: уровень -> форма -> факультет -> курс -> группа.

```python
from mtuci_timetable import LEVELS

client.forms("Бакалавриат")                      # ['Очная', 'Очно-заочная', 'Заочная']
client.faculties("Бакалавриат", "Очная")         # ['Информационные технологии', ...]
```

## Что нужно знать про сервер

**Год подставляет сервер.** В запрос уходит только номер месяца с нуля
(`8` - сентябрь). Год компонент достраивает сам по зашитому правилу, и на
границе учебного года оно даёт не тот год, которого ждёшь: в сентябре 2026-го
запрос января возвращает январь 2027-го. Поэтому при передаче `date` клиент
проверяет, что в ответе действительно есть запрошенный месяц, и иначе
поднимает `MonthUnavailable`. Доступно примерно +-4 месяца от текущего.

**Дата пары берётся из ключа, а не из `UF_DATE`.** Поле `UF_DATE` приходит
со сдвигом часового пояса и на границе суток указывает на предыдущий день.

**Перед сайтом стоит антибот, и решает он по User-Agent.** Запрос без него
получает `403 Access Blocked`, а обычный GET из не-браузера - страницу
«Вы человек?». С браузерным User-Agent, который клиент ставит по умолчанию,
эндпоинт отвечает нормально; куки и прохождение капчи не требуются.
Если у вас проверка всё же сработала, передайте куки из настоящего браузера:

```python
TimetableClient(cookies={"BITRIX_SM_MTUCI_GUEST_ID": "..."}, user_agent="...")
```

Проверить, что происходит на конкретной машине:

```bash
python -m mtuci_timetable.diagnose
```

## Данные

`Lesson` содержит дату, номер пары, дисциплину, время начала и конца,
преподавателей, аудитории, группы, вид занятия и флаги `is_retake`,
`is_online`, `is_form_control`. Сессия и пересдачи - это те же пары
с поднятыми флагами, отдельного эндпоинта под них нет.

Время может быть `None`: сервер помечает неизвестное значение двумя дефисами.
Исходный словарь всегда доступен в `lesson.raw`.

## Филиалы

По умолчанию - Москва (`SITE_ID=s3`). У ростовского и нижегородского
филиалов свои поддомены; для них передайте `base_url` и, вероятно, свой
`site_id`.
